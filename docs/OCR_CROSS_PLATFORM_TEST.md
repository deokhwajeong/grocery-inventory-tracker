# Cross-Platform OCR Test Guide

This document explains how to test the OCR functionality across different platforms.

## Platforms Supported

✅ **Windows Desktop** (Web Browser - Chrome, Edge, Firefox)
✅ **macOS Desktop** (Web Browser - Safari, Chrome, Firefox)  
✅ **iOS** (Native App via Capacitor or Mobile Safari)
✅ **Android** (Native App via Capacitor or Chrome Mobile)
✅ **Linux** (Web Browser - Chrome, Firefox)

## Testing Instructions

### 1. Web Browsers (Windows, macOS, Linux)

#### Desktop Testing:
```bash
# Start the Flask server
python app.py

# Open in browser:
http://localhost:5000/ocr
```

**Expected Behavior:**
- Camera button hidden on desktop (no built-in camera typically)
- Upload button allows selecting image files
- Works in all modern browsers (Chrome, Firefox, Safari, Edge)

#### Mobile Web Testing (iOS Safari, Android Chrome):
- Access the same URL from mobile device on same network
- Camera button should be visible and functional
- Uses HTML5 file input with `capture="environment"` attribute
- Can choose between camera or gallery

### 2. Native Apps (iOS & Android)

#### Build for Android:
```bash
# Add Android platform (one-time setup)
npx cap add android

# Sync web assets
npx cap sync android

# Open in Android Studio
npx cap open android

# Then build and run from Android Studio
```

#### Build for iOS:
```bash
# Add iOS platform (one-time setup, requires macOS)
npx cap add ios

# Sync web assets
npx cap sync ios

# Open in Xcode
npx cap open ios

# Then build and run from Xcode
```

**Expected Behavior:**
- Uses native Capacitor Camera API
- Requests camera permissions on first use
- Better performance and integration
- Auto-corrects image orientation

## Platform-Specific Features

### Camera Handler (`camera-handler.js`)

The `CameraHandler` class automatically detects the platform and uses the appropriate method:

1. **Native Apps (iOS/Android via Capacitor)**:
   - Uses `@capacitor/camera` plugin
   - Direct camera API access
   - Better image quality control
   - Automatic EXIF orientation correction

2. **Web Browsers (Desktop/Mobile)**:
   - Uses HTML5 file input
   - `capture="environment"` for mobile camera
   - Fallback for all browsers
   - Progressive enhancement

## Known Issues & Solutions

### Issue: Camera not working on iOS Safari
**Solution**: iOS requires HTTPS for getUserMedia API. Use ngrok or deploy to HTTPS server.

### Issue: Image orientation wrong on iOS
**Solution**: Already handled by `correctOrientation: true` in Capacitor Camera API.

### Issue: Permission denied on Android
**Solution**: Ensure permissions are declared in `AndroidManifest.xml` (auto-generated by Capacitor).

### Issue: OCR accuracy poor
**Solution**: 
- Ensure good lighting
- Keep receipt flat and straight
- Use higher quality camera
- Check `ocr_processor.py` preprocessing settings

## Development vs Production

### Development (localhost):
- Web browsers work fine
- Mobile browsers may have HTTPS restrictions
- Native apps connect to `http://localhost:5000` (see `capacitor.config.json`)

### Production:
- Deploy backend to server with HTTPS
- Update `capacitor.config.json` server URL
- Rebuild native apps
- Web version works from any HTTPS domain

## Quick Test Commands

```bash

# Check if Tesseract is installed
tesseract --version

# Test image preprocessing
python -c "from ocr_processor import preprocess_image; print(preprocess_image('test.jpg'))"

# Verify Python dependencies
pip list | grep -E "pytesseract|Pillow|opencv"
```
